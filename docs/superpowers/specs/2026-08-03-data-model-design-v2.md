## 0 · הממצא שממסגר מחדש — ולמה v1 לא הספיק

הגיליון מחזיק **שתי שורות לכל נתח** — מסלול A (סו-ויד+עישון) ומסלול B (עישון-בלבד) — עם ערכים
שונים לאותם שדות. `data.py` שיטח אותן לשורה אחת. נמדד (ההתאמה §2):

```
65 זוגות (שדה,פריט) שבהם המסלולים חלוקים ו-data.py מחזיק ערך אחד:
  tgt   24 פריטים   (בריסקט: A=94 · B=95 — data שמר את B; R-79)
  wrap  27 פריטים   (תמיד A="לא", B="כן" — data שמר את A → "127/130 לא")
  sear   8 פריטים   (A צורב, B לא — data שמר את A)
  coal   5 · wood 1
mid/somid — המקום היחיד ששני המסלולים שרדו (בשתי עמודות ad-hoc):
  route A (בריסקט): mid  ="צינון מלא"     → אין עטיפה, אין stall
  route B (בריסקט): somid="עטיפה ב-70°C"  → העטיפה היא שלב-עם-טריגר
```

**מסלול אינו תכונה של פריט; לפריט יש 0..n מסלולים, ולכל מסלול צעדים, יעד, פעולות ותזמון משלו.**
v1 (§4 שלו) מידל `route[]` יחיד לפריט — ולכן היה משמר את השיטוח בדיוק במקום שהוא נועד לתקן.

**ומדידה שנייה שמרחיבה את R-79:** ב-`sources.py` אין מפתח `tgt` בכלל (המפתחות: sv 130 ·
smoke 177 · safe 144 · verified 177 · grill 131 · cure 14). **כל 136 יעדי המרקם אינם מצוטטים** —
94°C של הבריסקט הוא מופע אחד של שכבה שלמה, ולכן `provenance:'craft'` הוא ברירת-המחדל של
השכבה, לא חריג של פריט.

## 4 · המסלולים — R-80, מיושר לגל 0 (מחליף את v1 §4)

### 4.1 · הזהות: המפתח הוא המפתח של `itemPaths`, מילה במילה

`itemPaths(meta)` (app.js:4760) כבר פולט מזהי מסלול: `id = methodKey` (= `'c:'+combo.sort().join('_')`
— למשל `c:sv`, `c:smoke`, `c:smoke_sv`) ועוד `':rev'` לסדר ההפוך (`order:'smoke-sv'`).
`effectiveSchedule(meta, sel)` הוא הדרך היחידה שכל משטח מקבל שלבים. `path_outcomes` (Dec-F1)
מתוכנן ב-`sources.py` על אותם מפתחות בדיוק.

**לכן `paths` במודל הוא מילון שממופתח באותם מזהים** — לא `route[]` עם מזהים עצמאיים. שני
מושגי-מסלול מתחרים היו חוזרים על טעות-השיטוח קומה אחת למעלה. גיליונות הבעלים הם שני איברים
של אותו אוצר-מילים: `02-sousvide-smoke.csv` ≡ `c:smoke_sv` (order:null) · `03-smoke-only.csv`
≡ `c:smoke`.

```yaml
paths:
  "c:smoke_sv":                       # מסלול A של הגיליון
    legs:                             # התזמון המצוטט של המסלול — מועבר, לא משוכתב
      sv:    { t: 68,  h: "30" }      #   ← data.svt/svh מילה-במילה (וגם sources.order_svsmoke)
      smoke: { t: 105, h: "3" }       #   ← data.smt/smh
    texture: { target_c: 94, provenance: owner-sheet }
    sear:  false                      # ← sheet-A "צריבה?"
    coal:  "Fogo Super Premium"
    steps:                            # R-80 — פעולות עם טריגרים, מהפרוזה של mid
      - { action: chill, trigger: { at_stage: { at: between-legs } }, note: "צינון מלא" }
      - { action: rest,  trigger: { when_safe_met: {} }, params: { min: 60 } }
  "c:smoke":                          # מסלול B של הגיליון
    legs:
      smoke: { t: 110, h: "12" }      #   ← data.sot/soh
    texture: { target_c: 95, provenance: craft }
    sear:  false
    coal:  "Fogo Super Premium"
    steps:
      - { action: wrap, trigger: { at_core_temp: { c: 70 } }, params: { material: butcher_paper } }
      - { action: rest, trigger: { when_safe_met: {} }, params: { min: 60 } }
  "c:smoke_sv:rev":                   # קיים רק כשיש order_smokesv מצוטט (13 פריטים) — מהציטוט, לא מומצא
    legs:  { smoke: { t: 75, h: "1.5-2", cold: false }, sv: { t: 68, h: "30", pasteurize: true } }
```

- **`wrap` הבינארי מת סופית**: אומת (ההתאמה §2.1) שב-27/27 הפריטים החלוקים הפעולה כבר חיה
  בפרוזת המסלול; הדגל לא נושא מידע. הוא לא מומר — הוא **נבדק**: `wrap=="כן"` בגיליון-B ⇔ צעד
  עטיפה/3-2-1 פוענח ב-`c:smoke`; אי-התאמה = שורת דוח, לא ניחוש.
- חמשת סוגי הטריגר הסגורים של v1 עומדים (`at_core_temp` · `after_elapsed` · `every` ·
  `at_stage` · `when_safe_met`), והמנוע מעריך עץ (`all_of`/`any_of` יכולת-מנוע, 0 כותבים).
  **התיקון:** נקודת-העגינה — טריגר יושב על צעד **בתוך מסלול**, לא על הפריט; ספירת v1
  (46/4/34/12/12) נמדדה על ה-mid/somid המשוטחים ולכן מתחלקת עכשיו בין `c:smoke_sv` ל-`c:smoke`.
- מה שאינו פעולה נשאר `notes` על הפריט (v1 §5 עומד; 171 העצות אינן אובדות).

### 4.2 · הגבול מול המנוע — "מדרג, לעולם לא מייצר"

הדוקטרינה (DECISION-HE-v2 §5 / p2-routing): וקטור התוצאה שייך **לציטוט**; המנוע גוזר **דירוג**,
לא לו"ז; אוסף המסלולים נשאר `itemPaths`; אפס מספר חדש. v2 מציית כך:

1. **המודל אינו מוסיף ואינו גורע מסלול.** `paths` ממלא בנתונים את המזהים ש-`itemPaths` פולט;
   שער G-5 (§7) מפיל בנייה על מפתח שאינו מזהה-`itemPaths` חוקי של הפריט — כולל כל מפתח של
   `path_outcomes`.
2. **`path_outcomes` נשאר ב-`sources.py`** (Dec-F1) והמודל **מפנה** אליו במפתח המשותף —
   לא משכפל אף שדה שלו. תוצאה = של הציטוט; צעדים/יעדים/תזמון = של המודל. חפיפה אסורה בסכימה.
3. **היכן v2 היה יכול להפר, ולכן נגדר:** ‏(א) שער הנגישות של טריגר בודק `at_core_temp.c ≤
   target_c` של **אותו מסלול** — השוואה, לא חישוב לו"ז; ‏(ב) הממיר **אינו משלים** ערך-מסלול חסר
   מהמסלול השני (למשל להעתיק את צעדי A ל-`c:sv` שהגיליון לא תיאר) — חסר = שורת דוח;
   ‏(ג) `time_h` לעולם אינו נכתב — הוא `Σ stage.hours` מ-`effectiveSchedule`, נגזר.
4. **N-7 של גל 0 ("עטיפה→שלב אמיתי") הוא הצרכן הראשון** של `paths[…].steps` — v2 מספק לו את
   הצורה; הוא אינו ממציא אחת משלו. תיקון דרישת נייר-הקצבים ב-E3 (`_wrap_gear` הרג'קסי) עובר
   לקרוא את הצעד.
