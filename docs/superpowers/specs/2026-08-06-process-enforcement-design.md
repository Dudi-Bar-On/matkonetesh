## 4 · שכבת הידע — `mk_rules`

### 4.1 · שני מסדים, כל אחד לתפקידו

| | קורא ממנו | למה |
|---|---|---|
| **hooks** | **`rules.sqlite`** | קובץ מקומי, אפס דיימון, מיקרו-שניות. ‏**Docker למטה? ל-hook לא אכפת** |
| **סוכן עמוק · ביקורת** | **PostgreSQL `mk_rules`** | ‏JSONB · היסטוריית גרסאות · הצטלבות עם הגניזה |

‏**‏DB נפרד** (`mk_rules`), לא סכימה בתוך הגניזה — החלטת בעלים. הגניזה היא ידע הפרויקט; זה מסד חוקים.

**‏6.8.26, 02:27:** המכונה אתחלה את עצמה, ‏Docker לא עלה, ‏Postgres נעדר שעות. בעיצוב הזה **האכיפה
הייתה ממשיכה לעבוד** — זה ההבדל בין הגנה שקיימת לבין הגנה שקיימת כשנוח לה.

### 4.2 · כיוון האמת — שלוש תחנות

```
docs/process/development-discipline.md   ← הסמכות. אדם כותב כאן.
        │  extractor (דלתא לפי content hash)
        ▼
   mk_rules (PostgreSQL)                 ← היטל מובנה
        │  mirror — חד-כיווני, אותם PK
        ▼
   rules.sqlite                          ← מה שה-hooks קוראים
```

**המסמך נשאר הסמכות.** אותה דוקטרינה כמו הגניזה עצמה (‏PostgreSQL מקור · Neo4j היטל):
**כלל שקיים במסד ולא במסמך הוא באג, לא כלל.**

**הבונה גוזר מה-disk, לא מ-git.** לא מ-staging, לא מ-`git diff`. כך `check-geniza-fresh` תפס
ב-6.8.26 שינוי **לא-מופקד** וריפא אותו. משמעות: שינוי בכלל נתפס גם אם לא הופקד, גם אם הקובץ מוחרג,
וגם אם ה-commit לא נגע בו.

### 4.3 · סכימה

```sql
rule_revisions(
  revision_id      uuid PRIMARY KEY,
  rule_id          text NOT NULL,          -- '10.17' · 'DoD-11' · 'H8' · 'L61'
  section          text,
  title_he         text,
  statement        text NOT NULL,          -- הציטוט מהמסמך, לא פרפרזה
  bucket           text CHECK (bucket IN ('A','B','C')),
  severity         text CHECK (severity IN ('warn','block')),
  mechanism        text,
  source_path      text NOT NULL,
  source_heading   text,
  source_hash      text NOT NULL,
  revision_status  text CHECK (revision_status IN ('current','superseded','retired')),
  is_current       boolean NOT NULL DEFAULT false,
  mirrored_at      timestamptz,
  created_at       timestamptz NOT NULL DEFAULT now(),

  -- הקבלה מדויקת ל-current_requires_both_sides של הגניזה:
  CONSTRAINT current_requires_mirror CHECK (
    NOT is_current OR mirrored_at IS NOT NULL)
);

rule_probes(rule_id text, probe_kind text, pattern text, applies_to text);
```

`rule_id` הוא **מזהה אנושי יציב שכבר קיים במסמך** — ולכן אין מיפוי מזהים, אין UUID לתרגם, אין
ריקונסיליאציה. אותה שורה, אותו מפתח, בשני המסדים. סנכרון = השוואת `(rule_id, source_hash)`.

**‏`current_requires_mirror` נושא את המשקל:** כלל אינו "בתוקף" עד שהוא הגיע ל-SQLite. **לא ייתכן
מצב שבו Postgres מכיר כלל וה-hooks לא — המסד עצמו אוסר זאת**, לא נוהל ולא זיכרון.

### 4.4 · מחזור חיים — כמו מסמך בגניזה

| אירוע | התנהגות |
|---|---|
| **נוסף** | ‏`§10.25` ללא `rule_id` → גרסה 1 |
| **עודכן** | ‏hash שונה → גרסה חדשה; **הישנה `superseded` ונשמרת** |
| **לא השתנה** | דילוג לפי hash |
| **הוסר מהמסמך** | ‏**`retired` עם תאריך — לא נמחק** |

**כלל שהוסר נשאר בר-שאילתה.** הבוקר שילמנו על ההפך: `memsync.py` נמחק, וששה באנרים המשיכו להפנות
אליו כאילו הוא חי. ‏hook שנתקל בהפניה לכלל ישן יאמר *"§X בוטל ב-<תאריך>, מחליפו §Y"*.

### 5.1 · מה הופך `Grep` ל"עבודה סימבולית"

מזוהה **רק כששלושתם מתקיימים**:

```
(א) היעד קוד     — type/glob של js|ts|py|… או נתיב src/, app.js
(ב) הדפוס סימבול — מזהה חשוף ^[A-Za-z_]\w*$ או def|function|class X
(ג) serena חיה   — ה-endpoint עונה
```

**כל השאר עובר בשקט.** חיפוש עברית, ביטוי עם רווחים, סריקת `docs/**` — מותר בלי שאלה. הטיה מכוונת
לאי-התערבות: **שער שמפריע לעבודה לגיטימית נלמד להיעקף.**

‏**‏(ג) הוא מה שמונע עונש על תקלת תשתית:** ‏serena מנותקת ⇒ **ה-`Grep` עובר בשקט מוחלט** — אין אזהרה,
אין רישום נפילה-ל-grep, כי אי אפשר לדרוש כלי שאינו זמין. *(קרה ב-6.8.26 — ‏39 כלי serena נותקו
באמצע session.)*

**⚠️ להסרת אי-בהירות מול §8.1:** נפילת serena **כן** מדווחת — אבל על-ידי **שכבה 0, פעם אחת**, כאירוע
תשתית. היא אינה מדווחת שוב על כל `Grep`. אחרת תקלת תשתית אחת הייתה מייצרת עשרות אזהרות זהות, וזה
בדיוק המנגנון שהופך שער לרעש.

**ההצהרה הופכת לרישום אוטומטי.** הכלל אומר `grep = fallback מוצהר`; ה-hook רושם את הנפילה
**בעצמו**, בלי לבקש דבר. אפס חיכוך, רישום מלא, **והבעלים רואה כל אירוע** בסיכום ה-session.

### 6.1 · מה נחשב "ניסיון תיקון"

עריכה אינה ניסיון. **ניסיון = מחזור סגור: אימות נכשל → עריכה → אימות שוב.**

```
pytest/playwright ≠ 0  ──► יעד = שם הבדיקה שנכשלה
Edit/Write על אותו יעד ──► המונה +1
אימות עבר             ──► המונה מתאפס
```

**המפתח הוא הבדיקה שנכשלה, לא הקובץ שנערך.** לרדוף אחרי שלושה כשלים שונים אינו "ניסיון רביעי" —
זה שלושה ראשונים. זה מה שמונע כשלי-שווא.

### 6.2 · שחזור מצב אחרי compact

‏`SessionStart` יורה כבר על `startup|resume|compact`, והכללים מוקראים מחדש. **אבל המצב לא.**
המונה שורד ב-SQLite; **הידיעה עליו לא.** אחרי compact הסוכן ניגש לתיקון הבא ומבחינתו זה ניסיון
ראשון — **§5 נשבר בדיוק שם, בשקט.**

```
=== ENFORCEMENT STATE, restored after compact ===
  §5      fix attempts on `model.py::_resolve_source`: 2 of 3
  §10.16  failures this arc: 4 · lessons logged: 1  ⚠ 3 uncovered
  infra   geniza OK · rules mirror OK · serena DISCONNECTED ⚠
```

‏`check-meta.mjs` כבר מנמק זאת בעצמו: *"compaction is exactly the moment the working memory
discipline depends on gets erased."* המנגנון קיים לכללים; המפרט מרחיב אותו למצב.

### 6.3 · מתי בדיוק §10.16 חוסם

**"סגירת קשת" אינו אירוע שמכונה יכולה לזהות, ולכן הוא אינו הטריגר.** במקומו, שני תנאים מדידים:

```
ב-commit:  כשלים שנרשמו ב-session הזה > 0
     וגם:  לא נוסף לקח (**L<n> ·) ולא הצהרת אי-לקח מאז ה-commit הקודם
     ⇒ חסימה
```

**החלופה התואמת קיימת ולכן החסימה לגיטימית:** לכתוב את הלקח, או להצהיר במפורש שאין לקח. שתיהן
לוקחות דקה. ‏`gate-lessons.mjs` הקיים מכיר רק `release(vNNN)` — כלומר קשת שלמה של עבודה רגילה
נסגרת היום עם אפס לקחים והשער נשאר ירוק. זו ההרחבה.
