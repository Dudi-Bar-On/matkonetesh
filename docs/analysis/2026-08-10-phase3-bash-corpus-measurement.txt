The controller read L51a's and 10.12a's "0 in-command" as "100% of the hits are prose noise".
That reading is WRONG for L51a, and the Phase-3 planner caught it before it reached the plan.

`sudo` inside `wsl` is ALWAYS quoted -- `wsl -e bash -lc 'sudo ...'` is the only shape the call
takes. The stripping pass removes quoted strings, so it removed THE SIGNAL, not the noise. The
same applies to L39: `$GEMINI_API_KEY` expands inside double quotes, which is exactly where an
echo of it would live.

So the "in-cmd" column means "survives blanket stripping", which is NOT the same as "is a real
command". For rules whose subject lives inside quotes it under-counts to zero. Those rules need a
stripping profile that keeps quote CONTENT and excludes prose structurally instead (the statement
must lead with `wsl` / a printer command).

The failure mode here is the one this whole arc keeps finding: a measurement returned zero and the
zero was read as absence rather than as a broken instrument. Sixth occurrence in one day.
