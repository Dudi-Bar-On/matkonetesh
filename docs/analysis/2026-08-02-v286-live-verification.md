# שורש הבעיה — Phase 1 של systematic-debugging

## 1. האם הקוד המתוקן בכלל רץ? **כן. נשלל כגורם.**

הבדיקה הזו לא דורשת AI כלל — `vcClaimVerdict` מיוצא ל-`window` (‏`app.js:8300`), אז אפשר לקרוא
את קוד המקור **שנשלח בפועל** מתוך הדף החי:

```
CACHEBUST LOAD1/2/3 → stamp="מהדורה 286 · 2.8.26"
                      has_internal_target_temp=true   has_c_gt_ref=true
                      swControlled=true  swScript="https://matkonetesh.pages.dev/sw.js"  regCount=1
PLAIN     LOAD1/2/3 → זהה בדיוק
```

שני פרופילים נקיים, ‏URL עם cache-bust ובלעדיו, שלוש טעינות רצופות כל אחד — כולל טעינות שבהן
ה-service worker כבר שולט בדף. בכל שש הטעינות: חותמת 286 **וגם** ענף השחרור החדש נוכח ב-JS
שרץ. **אין כאן shell מקוּשׁ ישן.**

## 2. מעקב ההחלטה בזמן ריצה — כאן 90°C ו-95°C הופכים ל-`[…]`

עטפתי את `vcGuardSpoken` ואת `vcClaimVerdict` בדף החי (הצהרות `function` ברמה העליונה הן
תכונות של האובייקט הגלובלי, ולכן הקריאה הפנימית עוברת דרך העטיפה) ותפסתי את הארגומנטים
והערך המוחזר האמיתיים. **הרצה 2, שאלת הבעלים:**

טקסט גולמי לפני השומר:
> …לבשר בקר היא 63°C עם מנוחה של שלוש דקות. אבל כדי שהאסאדו ייצא ממש רך ועסיסי, מומלץ להמשיך לבשל עד לטמפרטורה פנימית של **90°C עד 95°C**…

| טוקן | kind | conf | subject (מהמסווג) | `vcClaimSubjectSafeC` | verdict |
|---|---|---|---|---|---|
| `63°C` | `internal_safe_temp` | 1.0 | `{category:"beef", item:"beef"}` | **63** | `{verdict:"verified"}` |
| `90°C` | `internal_target_temp` | 1.0 | `{category:"beef", item:"asado"}` | **null** | **null → נצנזר** |
| `95°C` | `internal_target_temp` | 1.0 | `{category:"beef", item:"asado"}` | **null** | **null → נצנזר** |

**המסווג עשה הכל נכון.** הסיווג `internal_target_temp` נכון, הביטחון 1.0 (מעל הסף 0.85),
ו-`kind='single'` — כלומר גם שומר-הטווח בשורה 8252 לא חסם. הכשל הוא בשורה **8254**:

```js
const ref = vcClaimSubjectSafeC(cl);
if(ref==null) return null;                 // ← נופל כאן
…
if(cl.kind==='internal_target_temp' && c>ref) return {verdict:'release'};   // ← שורה 8268, לעולם לא מגיעים
```

**ענף השחרור החדש של v286 אינו ניתן להגעה עבור הטוקנים האלה.** הוא נכון, הוא נפרס, והוא מת.

## 3. האם המפתח במפה תואם את הטוקן? **תואם. הפרכה של השערת אי-ההתאמה.**

```
CLAIM MAP KEY : "90°C"  hex=[0039 0030 00B0 0043]   →  mapHit = true
TOKEN SCANNED : "90"    hex=[0039 0030]  @145
```

`vcClaimVerdict` נקרא עם `tokenText="90°C"` — בדיוק המפתח שבמפה, אותם ארבע נקודות-קוד,
‏`00B0` תקני, בלי רווח קשיח ובלי סימן מעלה חלופי. אין כאן באג של מפתח. הטווח גם לא נבדק
כיחידה מורכבת: כל מספר נבדק בנפרד עם `kind='single'`.

## 4. האם הנושא זוהה? — המסווג זיהה; **החיפוש בקטלוג נכשל**

זו הנקודה. `vcClaimSubjectSafeC` מריץ `askFindEntity(sub.item)`. בדיקה ישירה בדף החי:

| שאילתה | תוצאות | ראשונה |
|---|---|---|
| `askFindEntity('asado')` | **0** | — |
| `askFindEntity('אסאדו')` | 1 | heb="אסאדו", eng="Short Ribs", **safe=63** |
| `askFindEntity('beef')` | 13 | heb="שריר בקר (אוסובוקו)", eng="Beef Shank", safe=63 |
| `askFindEntity('בקר')` | 0 | — |

| נושא | `vcClaimSubjectSafeC` |
|---|---|
| `{category:"beef", item:"asado"}` ← האמיתי | **null** |
| `{category:"beef", item:"beef"}` | 63 |
| `{item:"אסאדו"}` | **63** |
| `{category:"beef"}` בלי item | null |

**המסווג מחזיר מזהי נושא באנגלית/תעתיק (`"asado"`, `"beef"`), והקטלוג מחופש לפי `heb`
ו-`eng` בלבד.** ‏"אסאדו" קיים בעברית ותורגם ל-‏"Short Ribs" באנגלית — המחרוזת `asado` לא
מופיעה באף אחד מהשדות. לכן `askFindEntity('asado')` מחזיר 0, והשורה 8290 מפעילה את
D2 — *"named an item we do NOT have → redact"*.

זה גם מסביר את **השונות בין הרצות** שנצפתה כאן ולפני התיקון: ‏`item:"beef"` **כן** מחזיר
פגיעות (13 — במקרה, דרך השדה `eng` של נתחים אחרים כמו "Beef Shank"), ולכן טענת ה-63°C
משוחררת. כשהמסווג במקרה כותב `item:"beef"` במקום `item:"asado"`, אותה שאלה בדיוק משחררת
את 90/95 — וזה מה שנצפה בהרצה `neg2-run2` (*"הוא צריך להגיע לסביבות 90°C עד 95°C"*).
התוצאה תלויה במילה שהמסווג בחר, לא בבטיחות.

> הערה נלווית שראוי לרשום: ‏`item:"beef"` נפתר ל-"שריר בקר (אוסובוקו)" — התאמת תת-מחרוזת
> לנתח לא-קשור. הוא מחזיר safe=63 שבמקרה נכון לקטגוריה, אבל זיהוי הנושא כאן הוא צירוף
> מקרים, לא זיהוי.

## מה נשאר בלתי-מוכרע

* **המכשיר של הבעלים.** כל הפרופילים שלי נקיים. לא יכולתי לבדוק אם ה-service worker במכשיר
