## 1 · Findings

### 1.1 · Settings — האם קיימת הגדרת יחידות, והאם היא "נכונה"?

**קיימת, אך היא הגדרת-AI בלבד — לא הגדרת תצוגה.** הרישום ב-`PREFS` (app.js:8668–8670):

```js

        he:'יחידות מידה', en:'Units', hintHe:'יחידות בתשובות ה-AI', hintEn:'Units in AI answers',
        opts:[{v:'metric',he:'מטרי (°C, ק״ג)'},{v:'imperial',he:'אימפריאלי (°F, lb)'}]},
```

**כל הקוראים של `pref('units')` — שלושה, כולם בוני-פרומפט של AI:**

| Reader | file:line | מה הוא עושה |
|---|---|---|
| `askGemini` system prompt | app.js:5358 | metric → מוסיף "השתמש תמיד ביחידות מטריות" |
| translation prompt (`metricLine`) | app.js:5595 | metric → "השתמש אך ורק ביחידות מטריות… לעולם לא °F/אינץ׳/lb" |
| voice-assistant system prompt | app.js:6538 | metric → "השתמש ביחידות מטריות בלבד (°C, ס״מ, ק״ג)" |

**אף נתיב-רינדור אינו קורא אותה.** כל התצוגה — כרטיסים, טבלאות, timeline, occupancy, copilot — מקודדת מטרית קשיח (ראו 1.2). מסקנות:

1. **זו אינה facade במובן "כותבת ואיש לא קורא"** — יש לה שלושה קוראים אמיתיים, וה-hint שלה מודה ביושר בהיקף ("יחידות בתשובות ה-AI").
2. **אבל היא אינה עומדת בדרישה 1 של R-26**: המשתמש שבוחר "אימפריאלי" לא רואה שום שינוי במסך כלשהו.
3. **פגם חי בערך `imperial`:** הבחירה ב-imperial רק *משמיטה* את שורת ה-metric-only מהפרומפטים (`pref('units')==='metric' ? line : ''`) — היא **אינה מבקשת אימפריאלי**. כלומר האופציה האימפריאלית כמעט ואינה עושה דבר, גם בתחום ה-AI שהיא מצהירה עליו.

**מה כן מפוזר — שתי משפחות:**

### 1.3 · הדאטה — איך יחידות מיוצגות בבסיס (השאלה הקריטית לדרישות 4/5)

**הבסיס כבר קנוני-מטרי — אבל היחידה מרומזת (implicit), לא מפורשת.** רשומת `data.py` אמיתית (שורה 6):

```python

```

`svt/smt/tgt/safe/sot` — מספרים חשופים שפירושם °C; `kg` — ק״ג. **אין אף ערך אימפריאלי מאוחסן כ-value מובנה** (grep `°F|fahrenheit` על data.py — אפס תוצאות).

**המקור האימפריאלי המצוטט שמור מילולית — אבל בפרוזה בלבד**, בהערות הציטוט של `sources.py` (279 ציטוטים, ממוזגים בזמן-בנייה). רשומות בפועל:

```

sources.py:772 — "Baldwin tough-cut window 55-80°C: '131°F (55°C) water bath for 24-48 hours' …"
sources.py:809 — "'Trichinosis is killed at 138°F and the new minimum recommended by USDA is 145°F' (145°F=63°C). …"
```

כלומר: דרישה 5 (בסיס מטרי/צלזיוס, "כמו העברית במילון") **כבר מתקיימת דה-פקטו** — ההמרה נעשתה ידנית בזמן כתיבת הדאטה, והמקור נשמר בציטוט. מה שחסר: (א) היחידה הקנונית אינה *מוצהרת* בשום מקום (schema יודע-יחידות אין); (ב) הערך המצוטט המקורי אינו שדה מובנה שניתן להציג/להשמיע — רק פרוזה.

### 1.4 · `__units__` — מה זה באמת, ולמה זה *לא* המרה

`tnode()` (app.js:8865) קורא `d.__units__` ומחליף **מילות-יחידה צמודות-ספרה** בלבד: `"53 פריטים" → "53 items"`, `ס״מ² → cm²`, `ל׳ → L` (lang/README.md:16). **המספר לא נוגע.** זו לקסיקוגרפיה — התרגום של *שם* היחידה — לא אריתמטיקה. האנלוגיה של הבעלים למילון נכונה **מבנית** (בסיס אחד ← נגזרות), אבל המנגנון הקיים פותר רק את ציר-השפה של יחידות; ציר-הסקאלה (63°C↔145°F) לא קיים בו, ואסור לערבב ביניהם: עיצוב שינסה "לתרגם" יחידות דרך המילון ימיר מילים בלי להמיר מספרים — בדיוק סוג הבאג שהוליד את R-26.

### 1.5 · Guard B — האינווריאנט, והאם רכיב-המרה מחזק או נלחם בו

Guard B (build.py:524–…) אוכף על מילוני-התרגום: **כל זוג מספר+יחידה במחרוזת המקור נשמר זהה בתרגום** (תופס °C↔°F, g↔kg פי-1000, min↔hr↔day, digit-drift; unclassifiable → FAIL CLOSED). כלומר האינווריאנט שלו הוא בדיוק עקרון-הבסיס של R-26: **המילונים לעולם אינם ממירים — הם נשארים בערכים הקנוניים.**

רכיב-המרה בזמן-ריצה **מחזק** אותו ואינו נלחם בו, בתנאי אחד: ההמרה קורית **אחרי** שכבת המילון (ברינדור/בדיבור), לעולם לא בתוך קבצי ה-lang. שני חיזוקים קונקרטיים: (א) `_GB_UNIT_CLASS` ייגזר מטבלת-היחידות האחת במקום להיות port מתוחזק-ביד; (ב) אם אי-פעם תוצג תצוגה אימפריאלית, Guard B ממשיך להבטיח שהמילונים עצמם נשארו קנוניים — ההפרה היחידה האפשרית תהיה בקוד, ששם הבדיקות.

## 3 · Design Proposal — רכיב `UNITS` (שם עבודה: Units Registry)

### 3.1 · עקרון-על
כמו העברית במילון: **הבסיס נשאר מטרי/צלזיוס וכתוב bare בדאטה — שום ערך מאוחסן לא משתנה.** הרכיב מוסיף שלוש יכולות מעל הבסיס: הצהרת-קנון, ייבוא-עם-יחידה, גזירת-תצוגה/דיבור.

### 3.2 · API

```js
// one kinds table — the single source for canon, conversions, classifier tokens, labels
const UNIT_KINDS = {
  temp:  {canon:'C',   conv:{'F':'F->C'},            labels:{he:'°C', voice_he:'מעלות'}},
  tempD: {canon:'Cdeg',conv:{'Fdeg':'Fdeg->Cdeg'}},   // delta/tolerance — NEVER the -32 branch
  mass:  {canon:'kg',  conv:{'lb':'lb->kg','g':'g->kg'}},
  vol:   {canon:'L',   conv:{'qt':'qt->L','gal':'gal->L'}},
  len:   {canon:'cm',  conv:{'in':'in->cm','mm':'mm->cm'}},
  area:  {canon:'cm2', conv:{'in2':'in2->cm2','m2':'m2->cm2','ft2':'ft2->cm2'}},
};

toCanonical(value, unit, kind)   // → {v, unit:canon, src:{v,unit}}  — the ONE import door;
                                 //   src keeps the external original verbatim (provenance)
classifyUnit(token)              // → {kind, unit} | null (fail-closed) — replaces the 5 duplicate
                                 //   classifiers; _GB_UNIT_CLASS is GENERATED from the same table
fmtUnit(value, kind, opts)       // → string — the ONE formatter for render AND voice
                                 //   opts: {lang, voice:false, cited:{v,unit}|null}
parseWithUnit(text, kind)        // subsumes propParse/PROP_SUFFIX_TO_CONV suffix logic
```

### 3.3 · מי צורך את מה
- **תצוגה:** אתרי-רינדור עוברים בהדרגה מ-`${x}°C` ל-`fmtUnit(x,'temp')`. כל עוד התצוגה מטרית-בלבד — הפלט זהה בייט-בייט, ולכן ההגירה בטוחה ומדידה.
- **קול:** ה-TTS בונה טקסט דרך `fmtUnit(…,{voice:true})` — היחידה תמיד נאמרת במילים ("מעלות צלזיוס"), והמספר תמיד הערך הקנוני. שער-הבטיחות הקולי (R-2/R-3) ממשיך לנרמל דרך `toCanonical` — ‏`aiSafetyToC` הופך wrapper דק שלו.
- **ייבוא חיצוני (מתכון, נתון בטיחות, ציוד, CP3):** חובה דרך `toCanonical`; ערך שמגיע בלי יחידה ולא ניתן לסיווג — fail-closed, כמו היום ב-`propCoerce` (החזרת null, המשתמש מקליד).
- **`pref('units')`:** נשאר המתג; אם יוחלט על תצוגה אימפריאלית — `fmtUnit` הוא הצרכן היחיד שלו, ואף אתר לא ממיר לבד.

### 3.4 · Safety provenance — איך ערך מצוטט שורד המרה
- **האחסון לא זז:** `safe:63` נשאר 63, עם המקור ב-`sources.py`. ההצעה מוסיפה שדה מובנה בציטוט: `cited={'v':145,'unit':'F'}` (ממוזג בזמן-בנייה כמו היתר).
- **תצוגה נגזרת, לעולם לא נגזרת-מחדש:** אם תוצג יחידת-המקור — מציגים את **המספר המצוטט המילולי** (145°F), לא re-derivation ‏(63°C→145.4°F). אין עיגול של ערך מצוטט, נקודה.
- **כשאין ציטוט ביחידת-היעד:** עיגול **כיווני-בטיחות בלבד** — רצפת-בטיחות מתעגלת כלפי מעלה (הצד הבטוח), לעולם לא מטה; טווח-סכנה מתרחב, לא מתכווץ. `Fdeg->Cdeg` נשאר מסלול נפרד לדלתאות (הלקח שכבר כתוב ב-app.js:166).
- **מה יכול להשתבש ואיך נמנע:** (א) המרה-כפולה (63→145.4→63.0) — נמנעת כי הבסיס לעולם לא נכתב מחדש; ‏`toCanonical` הוא דלת-כניסה, `fmtUnit` דלת-יציאה, ואין מסלול יציאה→כניסה. (ב) עיגול רצפה מטה — נחסם ב-assertion (DoD-10). (ג) דלתא שהומרה כטמפרטורה — ‏kind נפרד. (ד) מילון שממיר — Guard B כבר תופס.

### 3.5 · גורל ~N האתרים הקיימים
- **5 המסווגים:** מוחלפים ב-`classifyUnit` אחד (Guard B נגזר ממנו בבנייה). **מוחלפים, לא נשארים** — הם מוקד-הרגרסיות המוכח.
- **`UNIT_CONV`/`propCoerce`/`propParse`:** נבלעים לתוך הרכיב כ-implementation (ה-API החיצוני שלהם נשמר; שינוי מינימלי לציוד).
- **~150 אתרי-עיצוב:** **לא big-bang.** כל עוד התצוגה מטרית, אתר קשיח ≡ ‏`fmtUnit` — מהגרים פר-מסך, עם בדיקת byte-identity, רק כשנוגעים במסך ממילא (Circle of Control). מיגרציה מלאה נדרשת רק אם הבעלים רוצה תצוגה אימפריאלית בפועל.

## 4 · Sizing & Placement
